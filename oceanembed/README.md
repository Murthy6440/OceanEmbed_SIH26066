# OceanEmbed — SIH26066 Prototype

> ⚠️ **DEMO / SYNTHETIC DATA ONLY.** Every field, prediction, and metric in
> this project is generated by a parametric formula, not real satellite,
> Argo float, or in-situ ocean data. It exists to demonstrate the
> end-to-end pipeline for the SIH26066 problem statement. See
> [Dataset / Demo-Data Disclaimer](#dataset--demo-data-disclaimer).

## Problem Statement

SIH26066 asks for a way to estimate **subsurface ocean parameters**
(temperature, salinity) at a given depth, using only **surface observations**
— sea surface temperature (SST), sea surface salinity (SSS), sea surface
height / anomaly (SSH), surface currents, and surface winds. Direct
subsurface measurement (Argo floats, CTD casts, ship surveys) is sparse and
expensive; surface data (satellite altimetry, radiometry, scatterometry) is
comparatively abundant. The problem statement calls for an ML-based
estimator that bridges this gap.

## Solution

OceanEmbed is a working prototype of that pipeline, end to end:

1. A **synthetic ocean data generator** (`data_generator.py`) produces
   surface fields and a physically-inspired subsurface profile (thermocline-
   like exponential relaxation with depth) across a North Indian Ocean
   domain box (Arabian Sea + Bay of Bengal).
2. A small **PyTorch feed-forward network** is trained on that synthetic
   data to predict subsurface temperature & salinity from
   `[surface fields, depth, lat, lon]`.
3. A **FastAPI backend** exposes the trained model and the synthetic
   "ground truth" through a small REST API.
4. A **React + Leaflet + Plotly frontend** lets a user pick a location and
   depth on a map, run a prediction, and visually compare the model's
   output against the synthetic reference profile — including RMSE,
   correlation and bias.

This demonstrates the full ML + API + UI contract the real system would
need, so that the synthetic generator can later be swapped for real
satellite/Argo data without changing the architecture.

## Features

- Interactive Leaflet map of the North Indian Ocean domain, OpenStreetMap
  tiles, no API key required
- Click-to-select any point in the domain, or pick one of 10 named demo
  "virtual float" locations
- Depth slider (0–1000 m) that recolors the map's temperature layer and
  drives the point prediction
- PyTorch model inference through a documented REST API (`/docs`)
- Depth-vs-temperature profile chart (Plotly)
- Predicted-vs-reference ("demo ARGO") comparison chart
- Model validation metrics: RMSE, Pearson correlation, bias (temperature +
  salinity, computed on a held-out synthetic test split)
- Predicted-vs-observed scatter plot with a 1:1 reference line
- Backend status indicator + explicit demo-data disclaimer banner shown at
  all times, plus a `disclaimer` field on every API response
- Loading and error states on every async panel (map heatmap, profile
  charts, prediction card, validation metrics)

## ML Model

- **Task**: regress `[temperature °C, salinity psu]` from
  `[sst, sss, ssh, u_curr, v_curr, u_wind, v_wind, depth, lat_norm, lon_norm]`
  (10 input features → 2 outputs)
- **Architecture** (`model.py`, `OceanNet`): feed-forward MLP,
  `10 → 64 → ReLU → 64 → ReLU → 32 → ReLU → 2`, with light dropout (0.05)
  on the first two hidden layers during training
- **Training** (`train_model.py`): 20,000 synthetic training samples,
  5,000 held-out synthetic test samples, Adam optimizer, MSE loss,
  60 epochs, batch size 256. Features and targets are standardized
  (mean/std) with scalers persisted as JSON for portability
- **Artifacts** (`backend/saved_model/`): `oceanembed_model.pt` (weights),
  `scaler_x.json` / `scaler_y.json`, `validation_metrics.json`. The backend
  loads these on startup and only re-trains automatically if they're
  missing
- **Validation metrics** (on the synthetic held-out split): temperature
  RMSE ≈ 0.26 °C, correlation ≈ 0.999, bias ≈ +0.006 °C — this reflects fit
  to the synthetic formula, **not real-world skill**

## Dataset / Demo-Data Disclaimer

**There is no real oceanographic data anywhere in this project.** Every
surface field, subsurface profile, prediction, and validation number is
generated by the parametric formulas in `backend/data_generator.py` —
chosen to *resemble* plausible ocean behaviour (a thermocline-like
temperature decay with depth, monsoon-like wind patterns, smooth
eddy-like currents) purely so the pipeline has something realistic-looking
to train and demo against.

- Not sourced from satellites, Argo floats, moorings, or any in-situ survey
- Not validated against any real observation
- The "ARGO" comparison in the UI is against the generator's own synthetic
  reference profile, clearly labelled as a demo stand-in, not a real float
- Every API response includes a `disclaimer` field, and the UI shows a
  persistent disclaimer banner

This keeps the architecture and API contract ready to be pointed at a real
dataset (e.g. Argo NetCDF profiles, satellite SST/SSH products) without
redesigning the pipeline.

## Windows Setup Commands

Requires **Python 3.10+** and **Node.js 18+** installed and on `PATH`.
Run each block in its own terminal (PowerShell or Command Prompt).

```powershell
# --- Backend ---
cd backend
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
uvicorn main:app --reload --port 8000
```

```powershell
# --- Frontend (separate terminal) ---
cd frontend
npm install
npm run dev
```

Then open **http://localhost:5173** in a browser. No API key or `.env`
file is required to run the demo (the frontend defaults to
`http://localhost:8000` for the backend, and the map uses public
OpenStreetMap tiles directly).

## Backend Run Command

```bash
cd backend
pip install -r requirements.txt
uvicorn main:app --reload --port 8000
```

- API root: `http://localhost:8000`
- Interactive Swagger docs: `http://localhost:8000/docs`
- On first run, if `saved_model/` is missing, the backend trains the model
  automatically (~1 minute) before serving requests. Since this repo
  already ships a trained model, startup is instant.

```bash
cd frontend

```

- Dev server: `http://localhost:5173`
- Optional: copy `.env.example` to `.env` and set `VITE_API_BASE_URL` if
  the backend runs somewhere other than `http://localhost:8000`

## API Endpoints

All responses include a `disclaimer` field. Base URL: `http://localhost:8000`

| Method | Path | Description |
|---|---|---|
| GET | `/health` | Backend status + whether the model is loaded |
| GET | `/api/locations` | List of demo "virtual float" locations + domain box |
| GET | `/api/grid?resolution=3.0` | Synthetic surface field grid (SST/SSS/SSH/currents/winds) for the map |
| GET | `/api/profile/{location_id}` | Full 0–1000 m predicted + synthetic-reference profile for a demo location |
| POST | `/api/predict` | Predict temperature & salinity at a given `lat`, `lon`, `depth` (optional surface-field overrides) |
| GET | `/api/validation` | RMSE / correlation / bias on the held-out synthetic test split |

Example request:

```bash
curl -X POST http://localhost:8000/api/predict \
  -H "Content-Type: application/json" \
  -d '{"lat": 15.0, "lon": 70.0, "depth": 200.0}'
```

## Demo Presentation Flow

Suggested walkthrough for a SIH judging panel (~2–3 minutes):

1. **Open the dashboard** — point out the disclaimer banner and backend
   status indicator; state up front that this runs on synthetic data.
2. **Select a location** — pick a demo virtual float (e.g. "Central
   Arabian Sea") from the dropdown, or click a point on the map.
3. **Select a depth** — move the depth slider; note the map's colour layer
   updating live to show the subsurface temperature estimate at that depth.
4. **Generate Prediction** — click the button; the predicted temperature
   (and salinity) appear immediately, with the exact surface inputs used
   shown in the Model Inputs card.
5. **Show the profile** — point to the depth-vs-temperature chart: this is
   the model's estimate across the entire 0–1000 m column for the selected
   point, not just the one depth picked.
6. **Compare with demo ARGO** — the second chart overlays the model's
   prediction against the synthetic "reference" profile, explicitly
   labelled as a demo stand-in for a real Argo float.
7. **Show RMSE / correlation / bias** — the metric tiles quantify overall
   model fit against the held-out synthetic test set.
8. **Show predicted vs observed** — the scatter plot shows point-by-point
   agreement along the profile, coloured by depth, with a 1:1 line.
9. **Close** — reiterate that the architecture and API are
   dataset-agnostic: swapping `data_generator.py` for a real satellite/Argo
   data pipeline would plug into the same model, API, and UI unchanged.

## Limitations and Future Scope

**Current limitations**
- All data is synthetic; there is no real predictive skill on actual ocean
  conditions
- Domain is fixed to a North Indian Ocean box (5–30°N, 45–105°E)
- Model only predicts temperature and salinity — no currents, mixed-layer
  depth, or other derived quantities
- No authentication, database, or persistence — every request is
  computed fresh from the synthetic generator
- Map heatmap re-renders by calling `/api/predict` once per grid cell at
  the selected depth, which is fine for a demo grid but wouldn't scale to
  a fine-resolution production map without batching/caching on the server

**Future scope**
- Replace `data_generator.py` with a real data ingestion pipeline (Argo
  NetCDF profiles for ground truth, satellite SST/SSH/wind products for
  surface inputs) — the API contract and frontend would not need to change
- Extend the model to predict additional subsurface parameters (dissolved
  oxygen, currents at depth, mixed-layer depth)
- Add a server-side batch/grid prediction endpoint to avoid per-cell
  round trips for the map layer
- Add historical/time-series support (currently a single-time snapshot)
- Add authentication and rate limiting if exposed beyond a local demo
